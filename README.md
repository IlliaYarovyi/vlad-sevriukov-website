# Влад Севрюков — весільний ведучий

Односторінковий сайт, portовано з дизайн-прототипу Claude Design
(`Влад Севрюков - Весільний ведучий.dc.html`, проєкт
[claude.ai/design](https://claude.ai/design/p/1f0b52c8-0525-4074-8c05-b64b526b66a4)),
зібраний як звичайний Vite-проєкт: семантичний HTML, CSS на дизайн-токенах,
робоча форма заявки з бекендом на Telegram.

## Стек

- **[Vite](https://vitejs.dev)** — dev-сервер і збірка (бандлінг, мінізація, хешовані імена файлів)
- **Ванільні HTML/CSS/JS** — без фреймворку; сторінка достатньо проста, щоб React/Vue лише додали вагу
- **[@fontsource](https://fontsource.org)** — шрифти (Cormorant Garamond, Jost) самостійно захостені в білді, без запиту до Google Fonts у рантаймі
- **[d3-geo](https://d3js.org) + [topojson-client](https://github.com/topojson/topojson-client)** — проєкція/path і GeoJSON для карти України в розділі "Географія" (`src/ukraine-map.js`); лише ці два під-пакети, не весь d3, і забандлені як частина сайту, а не CDN `<script>`
- **Vercel Serverless Function** (`api/send-telegram.js`) — приймає форму заявки і пересилає в Telegram

## Запуск локально

```bash
npm install
npm run dev       # http://localhost:5173, форма заявки тут поверне помилку —
                   # serverless-функція не піднімається plain `vite dev`,
                   # див. розділ нижче
npm run build      # прод-збірка в dist/
npm run preview    # локальний перегляд прод-збірки
```

Щоб протестувати форму локально разом із функцією:

```bash
npm install -g vercel   # один раз
cp .env.example .env    # і впишіть туди свої TELEGRAM_BOT_TOKEN / TELEGRAM_CHAT_ID
vercel dev               # піднімає і статику, і /api/send-telegram.js
```

## Контактна форма → Telegram

### 1. Створіть бота

1. Напишіть [@BotFather](https://t.me/BotFather) в Telegram → `/newbot` → дайте імʼя.
2. BotFather видасть токен виду `123456789:ABCdef...` — це `TELEGRAM_BOT_TOKEN`.
3. Напишіть новому боту будь-яке повідомлення (наприклад «привіт») — боти не можуть
   писати першими, тож без цього кроку не отримаєте `chat_id`.
4. Відкрийте в браузері:
   `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates`
   і знайдіть у відповіді `"chat":{"id":123456789,...}` — це `TELEGRAM_CHAT_ID`.

### 2. Додайте змінні середовища у Vercel

Project Settings → Environment Variables:

| Name | Value |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен з кроку 1 |
| `TELEGRAM_CHAT_ID` | ваш chat id з кроку 1 |

Токен ніде не потрапляє в клієнтський код — його читає лише
`api/send-telegram.js` на сервері.

### 3. Як це працює

- `src/contact-form.js` шле `POST /api/send-telegram` з полями форми.
- Прихована поле-пастка (`name="company"`) відсіює найпростіших ботів —
  реальний відвідувач його не бачить.
- `api/send-telegram.js` перевіряє обовʼязкові поля, форматує повідомлення
  й відправляє через `sendMessage` Telegram Bot API.
- Є примітивний ліміт запитів на інстанс функції (5/хв на IP) — це не
  повноцінний rate-limiting (serverless-інстанси ефемерні), лише
  запобіжник від випадкового дабл-кліку/скрипта. Якщо форма колись стане
  ціллю справжнього спаму, поставте перед нею Vercel WAF/Cloudflare.
- Немає токена — форма коректно показує користувачу повідомлення про
  помилку замість падіння з 500.

## Hero-відео

Реальне промо-відео Влада (файл, наданий напряму — не з Instagram цього
разу). Грає одразу при завантаженні сторінки — беззвучно, зациклено.
Клік перетворює той самий `<video>`-елемент на центрований, зі звуком,
оверлей (`src/hero-video.js`) — не окремий lightbox, тому відтворення
продовжується з того ж місця, а не починається спочатку.

Розмір навмисно НЕ підігнаний під реальні пропорції відео (9:16), поки
згорнуто — це відповідає дизайну: `.hero-video` займає `min(820px,
100%)` завширшки з висотою через `padding-bottom: 75%` (широкий
"кінематографічний" кроп, `object-fit: cover` обрізає боки вертикального
відео), і тільки після розгортання переходить на справжні `aspect-ratio:
9 / 16` (`height: min(82vh, 760px)`, `width: auto`). Обидва стани — той
самий елемент, просто інший `padding-bottom`/`aspect-ratio` через клас
`.is-expanded`.

На десктопі розгорнутий стан — `position: fixed`, центрований по
viewport, з затемненим backdrop (`.hero-video-backdrop`) і
`overflow: hidden` на `body`. На мобільних (`max-width: 780px`) той
самий клас `.is-expanded` замість цього просто росте у потоці —
`position: relative`, `width: 100%`, той самий `aspect-ratio: 9 / 16`,
без backdrop і без `overflow: hidden` (`components.css`) — це навмисно:
`position: fixed`-центрування на мобільних має реальні проблеми (зміна
висоти viewport при показі/приховуванні адресного рядка серед іншого),
і повноекранний оверлей — не той патерн для малого екрану. Оскільки
блок росте на місці, а не спливає, `src/hero-video.js` після
розгортання (тільки коли `matchMedia('(max-width: 780px)')` активний)
викликає `wrap.scrollIntoView({ block: 'center' })` — це те, що
підсуває вищий блок у центр екрану, замість того, щоб він просто виріс
за межі видимої області знизу.

Файли в `public/media/`:
- `hero-full.mp4` — єдиний файл, що фактично використовується
  (`index.html`'s `.hero-video__player src`) — той самий елемент грає
  його беззвучно/зациклено, поки згорнуто, і зі звуком після кліку.
  Оновлений 2026-09-09 з нового промо-відео Влада (42.5s, `libx264
  crf 30`, ~6 МБ — помітно важче за попередній файл (33s, ~1.5 МБ), але
  й помітно краща якість джерела; для eager-завантажуваного hero-відео
  це прийнятний баланс)
- `hero-poster.jpg` — постер (кадр-обкладинка), кадр з ~1s нового відео
- `hero-preview.mp4` — той самий контент без звуку, перші 10s
  (lossless-обрізка `ffmpeg -t 10 -an -c:v copy`) — тримається в
  синхроні з `hero-full.mp4`, але наразі НЕ підключений в жодній
  розмітці/JS (архітектура спростилась до одного `<video>`-елемента на
  обидва стани — див. вище); лишається про запас, якщо колись
  знадобиться окремий легший файл для згорнутого стану.

Щоб замінити на інше відео: підставити новий файл під іменем
`hero-full.mp4` (або оновити шлях в `index.html`) і перегенерувати
`hero-poster.jpg`/`hero-preview.mp4` тим самим ffmpeg-пайплайном;
розмір/пропорції обох станів задані в `.hero-video` та
`.hero-video.is-expanded` в `components.css`, від самого відеофайлу не
залежать.

⚠️ Ще один нюанс з апдейту вихідного відео: наданий вихідний файл
(1920x1080) мав анаморфний SAR (`81:256`) замість квадратних пікселів —
тобто справжній видимий контент був ~608x1080 (9:16), а не 1920x1080
(16:9), як показували б сирі розміри пікселів без урахування SAR. Пряме
масштабування за пиксельними розмірами без цієї поправки дало б
спотворену (стиснуту по горизонталі) картинку. Виправлено через
`-vf "scale=trunc(iw*sar/2)*2:ih,setsar=1"` — домножує ширину на SAR
перед масштабуванням, а потім скидає SAR на 1:1 (квадратні пікселі) в
результаті.

⚠️ Нюанс, на який наткнулись під час білда: `.hero__media` раніше мала
`width: fit-content`, а `.hero-video` — власну ширину у відсотках від
неї — цикл, який резолвиться по-різному залежно від того, чи щось
щойно змусило браузер перерахувати стилі (наприклад, завершення
CSS-анімації), тож відео могло взагалі зникнути за ~1.5с після
завантаження. Тепер у `.hero__media` завжди задане конкретне значення
(`width: 100%; max-width: min(820px, 100%)`), без залежності від
розміру дочірнього елемента. Ще один нюанс з тієї ж історії: вступна
анімація — `fade` (тільки opacity), а не `rise` (opacity+transform) —
і це не просто косметика: завершена CSS-анімація, що займається
`transform`, лишає ненульовий computed `transform` навіть після
завершення (браузери повертають `matrix(1,0,0,1,0,0)`, не `none`), а
такий предок стає containing block для `position: fixed`-нащадків
замість viewport — саме це ламало центрування розгорнутого відео
раніше. `fade` цю категорію багів оминає повністю, бо ніколи не займає
`transform`.

## Портфоліо

Перебудовано в дизайн-синку 2026-09-12: 20 тайлів — 3 реальних
відео-кліпи (було 5 — `pf-7`/`pf-10` прибрані) + 17 реальних фото
(`pf-nN`, замінили попередній набір `pf-pN` з 10 фото). Відео-тайли
статичні (показують постер) — прев'ю грає лише під час наведення
(`src/portfolio-hover-preview.js`; клавіатурний фокус теж вмикає прев'ю,
для паритету); `<source>` лінива, довантажується коли тайл потрапляє у
viewport. Клік на відео-тайл (`[data-clip-src]`) відкриває просту
автоплей-модалку зі звуком (`src/clip-modal.js`) — без next/prev, без
кнопки "Переглянути в Instagram" (той функціонал прибрано разом з усією
секцією Instagram, див. нижче). Фото-тайли (`[data-lightbox-photo]`)
тепер клікабельні — це зміна порівняно з попереднім набором `pf-pN`,
який навмисно не був клікабельним: відкривають `src/gallery-lightbox.js`
з prev/next та лічильником "N / 17".

Під сіткою — новий рядок, що прокручується: список реальних імен
("ІМЕНА ЛЮДЕЙ, ЯКИХ Я ЗРОБИВ ЩАСЛИВІШИМИ"), той самий drift-механізм,
що й `.marquee` у hero, зі своїми шрифтом/кольором/швидкістю
(`.marquee--names`/`.marquee__track--names` в `components.css`).

Файли в `public/media/portfolio/`:
- `pf-1/2/3.jpg` + `-preview.mp4` + `-full.mp4` — 3 відео-тайли
  (постер / muted 6s 480px прев'ю / оригінал зі звуком), як і раніше
- `pf-nN.jpg` (N=1..17) — фото-тайли; змінені в розмір (`scale=
  'min(1600,iw)':'min(1600,ih)':force_original_aspect_ratio=decrease`,
  `-q:v 4`) з оригіналів на кілька МБ кожен

існуючими `--tl`/`--br` в `components.css`). Оригінал (86 МБ, 1920×1080)
стиснутий до 1280×720 (`crf 26`) — ~27 МБ для повного 2.5-хвилинного
виступу зі звуком прийнятно, коли він не автозавантажується.

## Географія

Замінено в синку 2026-09-12: статична сітка "3 міста" стала анімованою
SVG-картою України з пульсуючими маркерами 6 міст —
`<ukraine-map>` (`src/ukraine-map.js`), кастомний елемент.

Джерело дизайну малювало карту через глобальні `<script>`-теги d3 +
topojson-client з unpkg і `d3-selection` для побудови SVG. Тут замість
цього — лише два потрібних під-пакети (`d3-geo` для проєкції/path,
`topojson-client` для перетворення топології в GeoJSON) через npm,
забандлені Vite як і решта JS сайту; сам SVG будується напряму через DOM
API (`document.createElementNS`), без `d3-selection` — це узгоджується з
конвенцією сайту не тягнути рантайм-залежність з CDN (див. розділ про
самостійно захостені шрифти). З тієї ж причини топологія world-atlas
(~105 КБ, `public/data/countries-110m.json`) — локальний файл, а не
fetch з CDN, як у джерелі дизайну.

Крим у вихідних даних (Natural Earth/world-atlas) належить Росії —
`wholeUkraine()` в `ukraine-map.js` зливає його з Україною на рівні
топології (щоб спільна дуга розчинилась і не малювався внутрішній
кордон), а не просто перефарбовує колір.

## Cookie-банер і правові сторінки

Додано 2026-10-06: `privacy.html` (Політика конфіденційності) і
`cookies.html` (Політика використання cookie) — окремі статичні
сторінки, не секції `index.html`. Обидві використовують той самий
хедер/мобільне меню/футер, що й головна сторінка (посилання нав-меню
ведуть на `/#секція`, а не на `#секція`, бо ведуть із іншої сторінки), і
той самий темний дизайн-токен-набір, але власний легкий JS-вхід
(`src/legal.js` — лише шрифти/стилі, `initNav()` і cookie-банер, без
hero-відео/форми/лайтбоксів/карти, яких на цих сторінках немає).
Багатосторінкова збірка налаштована в `vite.config.js`
(`build.rollupOptions.input`) — без цього Vite білдить лише
`index.html`, і нові сторінки повернули б 404 на проді, хоч і працювали
б у `vite dev`.

Банер (`src/cookie-banner.js`, підключений і на `index.html`, і на обох
правових сторінках) — лише інформаційний, з однією кнопкою "Прийняти",
не gate з вибором "прийняти/відхилити": сайт **не встановлює** жодних
аналітичних чи рекламних cookie сьогодні (перевірено — немає
`document.cookie`, `gtag`, пікселів тощо в коді), тож немає чого
погоджувати в юридичному сенсі; банер лише інформує й ховається
назавжди через `localStorage` після кліку. Якщо колись додасться
аналітика/реклама — спершу оновити `cookies.html` з описом нових cookie,
і тоді вже переглянути, чи банеру потрібен справжній вибір
accept/decline.

Текст обох політик — стандартний шаблон під реалії сайту (хто обробляє
дані, які поля форми заявки збираються, навіщо, через які сервіси

Законом України «Про захист персональних даних»). Це не юридична

## Деплой (Vercel)

```bash
npm install -g vercel   # якщо ще не встановлено
vercel                  # перший деплой, запитає прив'язку проєкту
vercel --prod            # продакшн-деплой
```

Або підключіть репозиторій на [vercel.com/new](https://vercel.com/new) —
Vite-проєкти визначаються автоматично (`npm run build`, вихід у `dist/`),
`api/*.js` стають serverless-функціями без додаткової конфігурації.
